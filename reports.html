shown in the open.

Every example below is real output captured during development against targets Bulwark owns or is authorized to assess — a personal website, two personal GitHub repositories, and the local machine. Evidence is stored as JSON; human reports as standalone HTML.

Website vulnerability scan

www.tuiyabelong.com

Authorized scan via Bulwark's security shell: webscan https://www.tuiyabelong.com --full --sqli --xss. The scanner runs an HTTPS header audit, TLS protocol probes, sensitive path checks with soft-404 suppression, login form analysis, SQL injection and reflected XSS probes.

SeverityFindingFix advice issued by Bulwark
HIGHServer accepts deprecated TLS 1.0Disable TLS 1.0 in server configuration. For nginx set ssl_protocols TLSv1.2 TLSv1.3;. For IIS use the registry CryptoPolicy keys or IIS Crypto.
HIGHServer accepts deprecated TLS 1.1TLS 1.1 fails modern compliance baselines (PCI DSS). Restrict to TLS 1.2+ and retest.
MEDIUMMissing Content-Security-PolicyAdd a CSP response header starting in report-only mode, then enforce. A starter policy ships verbatim in the HTML report.
MEDIUMNo clickjacking protectionAdd X-Frame-Options: DENY or a frame-ancestors CSP directive.
LOWMissing X-Content-Type-OptionsSend nosniff to stop MIME confusion attacks.
LOWMissing Permissions-PolicyDisable unused browser features such as camera and microphone.
LOWMissing Referrer-PolicySet strict-origin-when-cross-origin to stop token leakage.
INFOHTTPS enforcedHTTP requests redirect correctly to HTTPS.
INFOTLS certificate validCertificate chain valid, issued by Let's Encrypt, not expiring within 30 days.
INFOJavaScript-handled login formForm posts via script rather than plain HTML submit; no plaintext credential probe attempted.

Evidence on disk. Every scan writes two artifacts to %ProgramData%\Sentinel\webreports\: a .json full evidence file (each check, request/response summary) and a standalone .html report openable in any browser. The numbers above are verifiable, not trusted.
